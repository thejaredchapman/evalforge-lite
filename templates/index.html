How to read this
  • Chat and interactive UIs — prioritize Response time (how long until the full answer arrives).
  • Long outputs (reports, code) — prioritize Speed (tokens per second).
  • Accuracy-critical work — choose Best quality.
  • If two models are within ~5 quality points, prefer the faster or cheaper one.
  • Run 3+ representative prompts before deciding — one prompt is noisy. Use "Repeat each prompt" for steadier timing.
  • Suggestions only name models from the same provider on the backend you used.
  • A judge can favor its own model family — for important decisions, re-run with a judge from a different provider.
  • "≈" speeds include hidden reasoning tokens on some providers and are approximate.
